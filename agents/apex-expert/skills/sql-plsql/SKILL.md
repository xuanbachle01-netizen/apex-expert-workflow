## Overview
Write correct, re-runnable Oracle SQL and PL/SQL for APEX apps, run it with SQL_Execute (user-approved) and confirm it compiled.

## Inputs
- The target schema, database version and APEX version from DB_Target (or the "Target:" lines of your task); write only SQL and APEX APIs that this version has.
- Existing objects: query `user_tables`, `user_tab_columns`, `user_constraints`, `user_objects` before creating or changing anything.

## Steps
1. Look up what exists (SQL_Query on user_* views). Reuse existing tables; never create a second table for the same data.
2. Write the script:
   - tables: `create table if not exists`; identity primary keys (`id number generated by default on identity primary key`), named constraints (`<table>_pk`, `<table>_<col>_fk`, `<table>_<col>_ck`), foreign keys indexed (`create index if not exists`).
   - views, packages, triggers: `create or replace`; packages as spec + body, business logic in packages, not in page processes.
   - seed rows: `merge into ... using (select ... from dual) ... when not matched then insert`.
   - changing an existing table: `alter table` guarded by a PL/SQL check of user_tab_columns, never drop/recreate.
   - end every SQL statement with `;` and every PL/SQL unit with a line containing only `/`.
3. Show the user in one or two sentences what the script changes, then call SQL_Execute (they approve it). For an app's own objects, put the script under app/supporting-objects/ instead (Install_App runs it on every install).
4. Read the result: errors (ORA-/PLS- with line), compile errors from user_errors, and INVALID objects. Fix and re-run until there are none.
5. Verify with SQL_Query (the rows, the columns, the object status).

## Rules
- Bind variables in all APEX SQL (`:P2_STATUS`), never string concatenation of user input. Use `apex_string.split`, `apex_util.string_to_table` for lists.
- No `exit`, `quit`, `connect`, `spool`, `host`, `@file` or `&` substitution in scripts: SQL_Execute refuses them.
- Only touch objects the request is about; the schema is shared with other apps. No drop/truncate unless the user asked for exactly that.
- APEX context from SQL (tests, jobs): `apex_session.create_session(p_app_id => 118, p_page_id => 1, p_username => '<an APEX user of the workspace>')` ... `apex_session.delete_session`. Inside the app use `:APP_USER`, `v('APP_ID')`.
- Logging: `apex_debug.info('msg %s', p1)`; error handling functions return `apex_error.t_error_result`.
- SQL_Query runs in a read-only transaction: test functions there only if they do not write.

## Example
Add a status column with allowed values: guarded `alter table tasks add (status varchar2(20) default 'OPEN' not null)` inside `declare l number; begin select count(*) into l from user_tab_columns where table_name = 'TASKS' and column_name = 'STATUS'; if l = 0 then execute immediate '...'; end if; end;` + `/`, then a named check constraint the same way; SQL_Execute; verify with `select column_name, data_type from user_tab_columns where table_name = 'TASKS'`.

## Gotchas
- `create table if not exists` does not change an existing table's columns; use guarded ALTERs for changes.
- A package body that compiles "with errors" stays INVALID and breaks every page that calls it: always check the INVALID list in the SQL_Execute result.
